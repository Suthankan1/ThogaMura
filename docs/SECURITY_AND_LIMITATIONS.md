# Security boundaries and honest limitations

**Local coursework MVP. Not production-ready.**

- Java command socket uses TLS (Member 5), certificate validation and fail-closed behavior. For local demonstration, certificates are generated by each developer and stored **outside** Git.
- UDP discovery is convenience only; it is spoofable and cannot authorize a remote server. Validate TLS identity after discovery.
- Java NIO feed is an **unencrypted version-only signal**, not a confidential business-data channel.
- REST/SSE gateway may use HTTP on localhost for class demonstration. Require HTTPS, authentication/authorization, CSRF policy and network hardening before use beyond trusted local dev.
- Browser, Next.js and API gateway must not hold PostgreSQL credentials.
- Use bounds for payloads, queue depth, clients and server worker threads. Apply I/O deadlines and close resources.
- A network timeout does not mean the operation failed. Retry with the same requestId and query authoritative status.
- No credentials, API keys, TLS private keys, personal data or real shop inventory in commits, issue attachments or AI prompts.
- Treat AI-generated suggestions and retrieved web pages as untrusted until reviewed and tested.

## Threat examples for demonstration

Forged UDP replies, untrusted TLS certificates, oversized TCP frames, disconnected NIO subscriber, concurrent stock race, ambiguous retries, unexpected payloads.

## Deferred for real operation

Human account login, per-action RBAC, audit identity, secured browser-to-gateway TLS, backups/restore procedures, rate limiting, secure admin workflows, wider-network deployment and third-party security review.

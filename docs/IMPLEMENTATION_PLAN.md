# ThogaMura implementation plan

**Repository baseline** `main` at `f8dba75`, reviewed 23 November 2026.

**Closeout.** The group approved ADR-008–010 and the protected workspace implements pagination, direct lookup, cancellation, receiving and branch permissions. The private-bridge checks and group-review package are complete. The two physical devices, personal contribution evidence, confirmed course information and Moodle upload are open. The findings below describe the original baseline. [Latest validation](VALIDATION_STATUS.md)

ThogaMura has a substantial networking implementation. The coursework demo already has real Java TCP framing, an independent HTTP supplier simulator, Java NIO fanout, PostgreSQL transactions and JSSE server authentication. The gaps that make the project feel unfinished appear when an operator loses a response, works with a long history, or has to decide whether displayed data can be trusted. Fix those paths first. Then present them in a coherent operator workspace and use a separate diagnostics view to demonstrate the network engineering.

Keep the existing topology. Next.js uses HTTP and SSE through Spring Boot. The gateway sends framed commands to a separate Java warehouse JVM over validated TLS. Only the warehouse JVM accesses PostgreSQL during application operation. The Java NIO port stays on a firewall-restricted private LAN and carries only version hints. Supplier stock remains advisory and comes from a separate HTTP process in the demo. Maintain one SKU per request, durable command UUIDs and `0 <= reserved <= on_hand` throughout the release. ### UI design direction

Design the primary workspace around three operator questions. What needs attention, what can I do now, and how current is the data? Keep the fox mark and teal as the brand accent. Use a neutral canvas, quieter borders, consistent spacing, readable text and tabular numerals. Reserve strong color for the main action, warnings and state changes. Move lecture explanations, sample SKU buttons, raw UUID controls and protocol terminology into diagnostics or a labeled demo disclosure. Use status text and icons together and prefer operational data over promotional illustrations.

Show pick and dispatch work with oldest pending age, stock shortages and network degradation, then a recent requests list that leads into the detail view. Render counts from authoritative data and show an as-of timestamp next to each independently loaded section. | Loading, cached, unavailable and real zero look distinct. Dashboard cards never claim whole-system totals from a single page. Focus stays stable during background refresh. |
| **Products** | Lead with item name, SKU and available units. Keep on-hand and reserved visible on desktop and easy to inspect on mobile.

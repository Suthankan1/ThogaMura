## 1. Executive Summary & Verification Baseline

### 1.1 Verification Observed During This Audit
- **Frontend Unit Tests:** Ran `npm test` inside `frontend/` — **49/49 tests across 11 suites passed** (`node --experimental-strip-types --test 'tests/**/*.test.ts'`).
- **Typecheck / Lint in Worktree:** `npm run typecheck` failed with `next: command not found` (`node_modules` is not installed inside this git worktree); `npm run build` / Playwright browser scripts and Maven `clean verify` were **not executed** in this worktree session. All code findings below are established directly by reading the current source files.

### 1.2 High-Level Verdict
ThogaMura is an unusually disciplined coursework system: its separation of browser HTTP/SSE from a separate-JVM Java TLS/TCP command server (`7443`), Java NIO selector invalidation feed (`7444`), outbound `HttpURLConnection` supplier adapter (`8090`), and PostgreSQL row-level locking (`SELECT ... FOR UPDATE` + `command_receipts`) is genuinely implemented and well-tested.

However, from a **daily operator's perspective** and a **Java systems engineering perspective**, the application suffers from:
1. **High-friction UX bottlenecks:** A 2.4-second full-screen blocking splash animation on every page reload; deadlocked write forms when an unconfirmed command remains in `sessionStorage` with no discard option; double network refetches after every workspace mutation; loss of query cache across tab switches; and bottom-placed sign-out/branch identity in `/workspace`.
2. **Modern UI & Motion Gaps:** Aside from the impressive `BrandIntro` SVG animation, operational screens lack drawer/dialog entrance transitions, loading skeletons, floating action toasts, row-update highlight pulses, and visual stock-allocation bars.
3. **Unresolved Backend & Protocol Traps:** `JdbcStockMovementRepository.findAll()` still queries `ORDER BY id ASC LIMIT 500` (hiding new dispatches once >500 exist); Protocol v1 list frames (`MAX_QUERY_LIMIT = 500`) will exceed `MAX_FRAME_BYTES = 65_536` (~64 KB) and fail around ~350–400 requests; `TcpCommandClient` opens a fresh TCP + TLS handshake per request instead of pooling connections; `InventoryWorkerPool` uses `CallerRunsPolicy` on the accept path; `DefaultSupplierHttpClient` treats optional `estimatedRestockDays` as mandatory; and `GatewayNioSubscriber` relies on OS TCP keepalives (~16s+ outage detection) instead of an application-level NIO heartbeat.

## 3. Modern UI/UX & Animation Comparison

### 3.1 What ThogaMura Already Does Well
- **Calm, credible operational palette:** Teal (`#0f766e`) on crisp slate canvas (`#f8fafc`), high-contrast ink (`#0f172a`), `Inter` variable weights (`@fontsource/inter`), and consistent `tabular-nums` alignment on counts/quantities.
- **Container-query responsiveness:** Using `@container` in [`globals.css`](../frontend/src/app/globals.css#L127-L141) (`.stock-exceptions`) and [`records.css`](../frontend/src/components/records.css#L1-L48) (`.records`) adapts tables into structured cards cleanly at narrow widths without JS resize listeners.
- **Safety-first UX:** Preserving `Idempotency-Key` across uncertain timeouts, formula-injection-safe CSV export (`'=...`), and `prefers-reduced-motion` / `prefers-reduced-transparency` / `forced-colors` media queries.

### 3.2 Where It Falls Short of Modern WMS / SaaS Standards (Linear, Shopify Admin, Stripe)
1. **Motion Imbalance (Cinematic Intro vs. Flat Operations):**
   - `BrandIntro` has choreographed SVG clip-path masking, cable path-length tracing (`stroke-dasharray`), spark fade, and sonar ring pulse (`2.4s`).
   - Once inside the app, **every operational state change is abrupt**: mobile drawers snap open/closed, `<dialog>` detail drawers pop without slide-over easing, tab switches hard-replace the DOM, and loading states show plain text (`"Checking warehouse…"`) instead of skeleton shimmer placeholders.
2. **Missing Functional Micro-Interactions:**
   - **Live Update Highlight:** When Java NIO → SSE triggers a refresh and an item's `available` count drops or a request moves from `ACCEPTED` → `PICKED`, there is no subtle 1.5s teal/amber row flash (`@keyframes row-updated`) to guide the operator's eye to *what changed*.
   - **Floating Live Toasts:** Mutation confirmations (`notice` / `feedback`) render statically at the top of the page. On a 24-row list, clicking *Pick* or *Reserve* scrolled halfway down gives no visible confirmation without scrolling back up.
   - **Visual Stock Allocation Bar:** Modern inventory grids show a compact 4px stacked progress bar (`reserved` in amber + `available` in teal over `onHand` track) so shortages and heavy holds read at a glance in 200ms.
   - **Sticky Table Headers & Command Palette (`⌘K` / `Ctrl+K`):** Operators juggling Inventory, Requests, and Suppliers benefit hugely from a keyboard quick-jump (`/` to focus search, `⌘K` to jump to any SKU or Request UUID).

## 4. Stakeholder Perspectives, Feelings & Feedback

### 4.1 Shop / Branch Operator (Counter Staff — Rush Hour)
> *"When a customer is standing at the counter asking for 12 crates of carrots, I open ThogaMura and get hit by a 2.4-second fox animation every time I refresh the page. In `/workspace`, I have to scroll past the whole table just to double-check I'm signed in under `branch-north` and not `branch-south`. Clicking 'Reserve' from the product list puts the SKU into a form, which is nice, but if the Wi-Fi hiccups and gives me 'Awaiting confirmation', all my other buttons lock up and I can't even discard a stale draft if I decide to order something else. When stock is 0 and I check the supplier, I just want to see clearly whether the supplier has 0 units or their server is down—in the workspace it just says 'Supplier availability unknown' for both!"*
- **Key Need:** Session-once splash, top-bar branch badge, discardable pending state after verification, clear supplier error states, and quick `-`/`+` quantity controls.

### 4.2 Warehouse Picker & Dispatcher (Floor Staff on Tablet)
> *"When I log in to the workspace, why do I land on Overview instead of my Fulfillment Queue? When I'm walking the aisles with a tablet in landscape mode, the navigation tabs jump up and down depending on which tab I'm on. In the demo queue, 'Mark picked' happens immediately on one tap—my thumb accidentally hit it twice while scrolling—and in the Movements tab I can't see the product name next to the SKU, only `ITEM-007`, so I have to memorize SKU codes!"*
- **Key Need:** Role-based landing (`PICKER` → `queue`), stage badge counts (`To pick (5)`), `productName` in the movements ledger, consistent `updatedAt` wait age, and unobtrusive toast confirmation near the bottom/top viewport.

### 4.3 Warehouse Supervisor (Operations Manager)
> *"I love that receiving stock asks me to review the numbers and a note before changing on-hand balances, and that we can assign a supplier follow-up owner with a due date so two staff don't call the supplier twice. But when I edit a follow-up and hit Save, the edit box stays stuck open! Also, when I export the ledger CSV from the workspace, it only exports the current 16-row page (`Export this page`) instead of my full filtered date range, and the movements list doesn't show the product name."*
- **Key Need:** Fix stuck `FollowUp` edit form, multi-page or server-bounded filtered CSV export (within safe frame limits), `productName` in ledger, and low-stock threshold visibility on Overview.

### 4.4 Lecturer / Academic Grader (Java Network Programming Assessment)
> *"The architecture separation is genuinely impressive—no REST-to-DB shortcuts, real JSSE `SSLSocket`, non-blocking `Selector` + `ByteBuffer` partial-write handling, `HttpURLConnection` to an independent mock server, and PostgreSQL `SELECT FOR UPDATE` + `command_receipts`. What I still want to see live in the UI during a demo is: (1) a one-click `PING` button on `/activity` proving round-trip TLS latency and server timestamp; (2) faster NIO outage detection (< 6s via heartbeat instead of waiting 16s for OS TCP keepalive); and (3) proof that a list of 500 demo requests doesn't silently blow up the 64 KB TCP frame ceiling!"*
- **Key Need:** Expose `GET /api/v1/ping` interactively on `/activity`, add NIO application heartbeats, fix `JdbcStockMovementRepository` sort order, and keep every new feature strictly mapped to M1–M5 with negative tests.

### 4.5 Security & Network Engineer / SysAdmin
> *"The cryptographic hygiene is solid—600k-iteration PBKDF2, HMAC-SHA256 short-lived assertions, strict RFC 2818 SAN verification, SSRF origin allowlisting, loopback-only NIO defaults, and formula-safe CSV quoting. Two operational risks worry me in a two-laptop LAN demo: first, `WorkspaceAccess` only tolerates 5 seconds of clock skew (`now + 35s`), so two laptops without NTP sync will fail with mysterious `403 FORBIDDEN` errors; second, `TcpCommandClient` creates a brand-new TLS socket per HTTP request, multiplying handshake overhead under burst load. Also, port 7443 currently authenticates only the server, not the gateway (no mTLS yet)."*
- **Key Need:** Clock-drift indicator via `PING` `serverTime`, persistent TLS socket pooling, optional mTLS (`needClientAuth`) on port 7443, and `SSLEngine` protection if NIO ever leaves a private LAN.

### 4.6 Accessibility & Frontend Quality Reviewer
> *"Great progress since Nov 23: `min-h-11` targets, `aria-busy`, `aria-live`, container queries, and `forced-colors` support are thoughtful. Remaining gaps: `ProductPicker` needs proper ARIA `combobox` + keyboard arrow navigation; `BalanceChange` injects 16 empty `role="status"` elements per page and mutates state during render; `BrandIntro` locks `inert` on every refresh; and mobile drawers lack smooth reduced-motion-safe transitions."*

### 6.2 Invalid / Rejected Feature Ideas (Filtered Out by the Validity Gate)
To prevent scope creep or accidental contract violations, the following ideas were **explicitly rejected** during double-checking:
- **UDP Multicast / Broadcast Warehouse Discovery:** Rejected by ADR-006 and `AGENTS.md` (browsers cannot use UDP, fragile on routed/firewalled LANs, weakens TLS identity pinning).
- **Offline Browser Mutation Queue (IndexedDB Sync):** Rejected by `PROJECT_CONTEXT.md` ("no offline mutation queues; central PostgreSQL remains the sole inventory authority").
- **Optimistic Stock Decrements in Browser Memory:** Forbidden by `frontend.md` ("Stock values remain server-authoritative; SSE is an invalidation signal only").
- **Direct Gateway-to-PostgreSQL Reads for Performance:** Forbidden by `AGENTS.md` ("Only `network-server` accesses PostgreSQL").
- **User-Supplied Supplier URLs in UI:** Forbidden by `SUPPLIER_HTTP_V1.md` (SSRF vulnerability).
- **Automated Purchase Orders / Invoicing / Accounting:** Forbidden by `PROJECT_CONTEXT.md` (out of coursework scope).
